# Sign in with Face ID (Passkeys) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A member who signed in once with an emailed code or Google can turn on Face ID (fingerprint on Android, a passkey elsewhere) and sign in with it from then on; a device that set it up opens to a "Welcome back" screen.

**Architecture:** Better Auth's passkey plugin (`@better-auth/passkey`, SimpleWebAuthn underneath) supplies registration and sign-in. A server-set cookie remembers which passkey this device created, so the sign-in page, the offer sheet, and Settings decide what to show on the server with no flash. Device wording comes from the user agent on the server. Listing and removing passkeys go through our own domain module with an owner check, like every other group operation.

**Tech Stack:** Next 16 (App Router, server actions, `cookies()`/`headers()`), Better Auth 1.6 + `@better-auth/passkey`, Drizzle + Postgres, zod v4, Base UI Dialog, lucide-react, Vitest (node environment), Playwright (Chromium CDP virtual authenticator).

**Spec:** `docs/superpowers/specs/2026-11-15-passkeys-design.md`. Mockups: https://claude.ai/artifact/FY1HUAZMnNkyttZo2sdc5C

## Global Constraints

- Server env via `env` from `src/lib/env.ts`, never `process.env`. Zod stays out of `"use client"` files and `src/lib/passkey-device.ts` (browser-shipped).
- Server actions parse input with zod, return `issues[0].message` as inline copy, and call `logRefusal(err)` first in their refusal mapping. Never re-export types from a `"use server"` file; clients import `ActionState` from `@/app/(app)/group/actions`.
- Revalidate `revalidatePath("/(app)", "layout")`, never the root layout (`src/revalidation.test.ts`).
- Every tappable element is `<Button>`/`buttonVariants` with a fill or border (`src/components/button-styling.test.ts`). No floating text links.
- No em dashes in any UI copy, error string, or What's new entry.

- Passkey domain: `env.PASSKEY_RP_ID ?? new URL(authBaseURL).hostname`. `rpName: "Small Group"`. Origin: `authBaseURL`.
- Welcome back never opens the OS prompt on its own: the member taps the button.

## Decisions made while planning (spec updated to match)

- **Server cookie instead of `localStorage` for "this device's passkey".** `sg_passkey` holds the id of the passkey this device created. It is httpOnly and set by a server action, because Safari caps cookies written from JavaScript at 7 days. With it the server renders Welcome back and "This iPhone" directly. `localStorage` keeps only the "offered" flag, `sessionStorage` the "just signed in" note.
- **List and remove through `src/lib/passkeys.ts`**, not the plugin's endpoints, so ownership is checked in our code and covered by our integration tests, and the public key never leaves the server.
- **Any passkey sign-in sets the cookie again.** Clearing site data (or deleting and re-adding the home-screen app) drops `sg_passkey`, but the passkey stays in the phone's password manager and still works from the email field's suggestions. After such a sign-in the server sets the cookie again, so Welcome back returns from the next visit. The server can't tell which passkey was used, so it picks the member's only passkey, or the only one named for this kind of device. Otherwise it stores `unknown`, which brings Welcome back but marks no Settings row "This iPhone".
- **Mac user agents are named "Mac".** iPadOS Safari reports a Mac user agent, so an iPad's passkey is labeled "Mac". The spec accepts that a wrong guess only mislabels.

```ts
// The domain passkeys are bound to (WebAuthn's relying party id). It defaults
// to the auth origin's host. PASSKEY_RP_ID overrides it, so after a move to a
// new domain the old one can stay the passkey domain and existing passkeys
// keep working through WebAuthn related origins (spec: "Passkey domain").
export function passkeyRpID(baseURL: string, override?: string): string {
  return override ?? new URL(baseURL).hostname;
}
```

```ts
// Passkey wording and device state. Pure and browser-safe (no zod, no server
// imports): the server picks wording from the user agent, and client
// components use the browser checks and storage helpers.
// Spec: docs/superpowers/specs/2026-11-15-passkeys-design.md

export type PasskeyKind = "face-id" | "fingerprint" | "passkey";

export type PasskeyMethod = {
  kind: PasskeyKind;
  // Names a new passkey. Members can't rename them.
  deviceName: string;
  // Labels the passkey this device created in Settings.
  thisDevice: string;
  device: "phone" | "tablet" | "device";
};

// A wrong guess only mislabels the button: the OS shows its own prompt.
// iPadOS Safari sends a Mac user agent, so an iPad reads as a Mac.
export function passkeyMethod(userAgent: string): PasskeyMethod {
  if (/iPhone/.test(userAgent)) {
    return { kind: "face-id", deviceName: "iPhone", thisDevice: "This iPhone", device: "phone" };
  }
  if (/Android/.test(userAgent)) {
    return /Mobile/.test(userAgent)
      ? { kind: "fingerprint", deviceName: "Android phone", thisDevice: "This phone", device: "phone" }
      : { kind: "fingerprint", deviceName: "Android tablet", thisDevice: "This tablet", device: "tablet" };
  }
  if (/Macintosh/.test(userAgent)) {
    return { kind: "passkey", deviceName: "Mac", thisDevice: "This Mac", device: "device" };
  }
  return { kind: "passkey", deviceName: "Computer", thisDevice: "This computer", device: "device" };
}

export function kindForDeviceName(name: string | null): PasskeyKind {
  if (name === "iPhone") return "face-id";
  if (name?.startsWith("Android")) return "fingerprint";
  return "passkey";
}

const NAMES: Record<PasskeyKind, { feature: string; with: string; unlocks: string }> = {
  "face-id": { feature: "Face ID", with: "Face ID", unlocks: "Your face unlocks Small Group on this phone." },
  fingerprint: {
    feature: "Fingerprint sign-in",
    with: "fingerprint",
    unlocks: "Your fingerprint unlocks Small Group on this phone.",
  },
  passkey: {
    feature: "Passkey sign-in",
    with: "a passkey",
    unlocks: "Your device's screen lock signs you in.",
  },
};

export type PasskeyCopy = ReturnType<typeof passkeyCopy>;

export function passkeyCopy(method: PasskeyMethod) {
  const n = NAMES[method.kind];
  const turnOn = method.kind === "face-id" ? "Turn on Face ID" : `Turn on ${n.feature.toLowerCase()}`;
  return {
    signInButton: `Sign in with ${n.with}`,
    signInFailed: `Couldn't sign in with ${n.with}. Try again, or use email instead.`,
    cardTitle: method.kind === "passkey" ? "Passkeys" : n.feature,
    explainer:
      method.kind === "face-id"
        ? "Sign in with a glance instead of waiting for an email code."
        : method.kind === "fingerprint"
          ? "Sign in with your fingerprint instead of waiting for an email code."
          : "Sign in with your device's screen lock instead of waiting for an email code.",
    turnOn,
    turnOnHere: `${turnOn} for this ${method.device}`,
    turnOnFailed: `Couldn't turn on ${n.feature.toLowerCase()}. Try again from Settings.`,
    offerTitle: `Sign in with ${method.kind === "fingerprint" ? "your fingerprint" : n.with} next time?`,
    offerBody: `Skip the email code. ${n.unlocks}`,
    removedNotice: `${n.feature} was turned off for this ${method.device}. Sign in with an email code, then you can turn it back on in Settings.`,
  };
}

// Better Auth's passkey client returns `{ error: { code, message } }`.
// Cancelling the OS sheet surfaces as AUTH_CANCELLED on sign-in and a
// ceremony-aborted or NotAllowedError on registration. iOS also reports "no
// passkey for this site" as NotAllowedError, which is why a device without one
// never shows the button.
export function passkeyErrorKind(
  error: { code?: string; message?: string } | null | undefined,
): "cancelled" | "removed" | "other" {
  if (!error) return "other";
  if (error.code === "PASSKEY_NOT_FOUND") return "removed";
  if (
    error.code === "AUTH_CANCELLED" ||
    error.code === "ERROR_CEREMONY_ABORTED" ||
    /NotAllowedError|AbortError/.test(error.message ?? "")
  ) {
    return "cancelled";
  }
  return "other";
}

export function passkeySupported(): boolean {
  return typeof window !== "undefined" && typeof window.PublicKeyCredential === "function";
}

export async function platformPasskeyAvailable(): Promise<boolean> {
  try {
    return passkeySupported() && (await PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable());
  } catch {
    return false;

export async function conditionalMediationAvailable(): Promise<boolean> {
  try {
    return passkeySupported() && (await PublicKeyCredential.isConditionalMediationAvailable?.()) === true;
  } catch {
    return false;
  }
```

```ts
import { and, asc, eq } from "drizzle-orm";
import { db } from "@/db/client";
import { passkey } from "@/db/schema";

// Passkeys are listed and removed here rather than through the plugin's
// endpoints, so ownership is checked in our code (and tested) and the public
// key never leaves the server. Registration and sign-in stay with the plugin.

export type PasskeySummary = { id: string; name: string | null; createdAt: Date | null };

export async function passkeysFor(userId: string): Promise<PasskeySummary[]> {
  return db
    .select({ id: passkey.id, name: passkey.name, createdAt: passkey.createdAt })
    .from(passkey)
    .where(eq(passkey.userId, userId))
    .orderBy(asc(passkey.createdAt));
}

export async function ownsPasskey(userId: string, id: string): Promise<boolean> {
  const rows = await db
    .select({ id: passkey.id })
    .from(passkey)
    .where(and(eq(passkey.id, id), eq(passkey.userId, userId)));
  return rows.length > 0;
}

// Takes effect at once: the next sign-in with this credential is refused.
export async function removePasskey(userId: string, id: string): Promise<void> {
  const rows = await db
    .delete(passkey)
    .where(and(eq(passkey.id, id), eq(passkey.userId, userId)))
    .returning({ id: passkey.id });
  if (rows.length === 0) throw new Error("not-found");
}

// Which of the member's passkeys this device most likely holds, for setting
// the sg_passkey cookie again after a passkey sign-in. Only a guess that
// can't be wrong: the member's only passkey, or the only one named for this
// kind of device. Otherwise null.
export async function passkeyForDevice(userId: string, deviceName: string): Promise<string | null> {
  const all = await passkeysFor(userId);
  if (all.length === 1) return all[0].id;
  const named = all.filter((p) => p.name === deviceName);
  return named.length === 1 ? named[0].id : null;
}
```

```ts
  _prevState: ActionState,
  formData: FormData,
```

```ts
// lost (site data cleared, app re-added) but the passkey wasn't: set it again
// so Welcome back returns from the next visit. Needs the session the sign-in
// just created; does nothing without one.
```

```tsx
} from "@/lib/passkey-device";

// Offered once per device, only right after a code or Google sign-in in this
// tab (the sign-in form's note), never on top of the What's new popup, and
// never where the device can't make a platform passkey.
export function PasskeyOffer({
  method,
  hasPasskey,
  whatsNewShowing,
}: {
  method: PasskeyMethod;
  hasPasskey: boolean;
  whatsNewShowing: boolean;
}) {
  const router = useRouter();
  const copy = passkeyCopy(method);
  const [open, setOpen] = useState(false);
  const [pending, setPending] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    if (!hasJustSignedIn()) return;
    if (hasPasskey || whatsNewShowing || wasOffered()) {
      takeJustSignedIn();
      return;
    }
    // The note is taken only when the sheet really opens, so StrictMode's
    // second effect run (after the first is cancelled) still finds it.
    let cancelled = false;
    void platformPasskeyAvailable().then((available) => {
      if (cancelled) return;
      takeJustSignedIn();
      if (!available) return;
      markOffered();
      setOpen(true);
    });
    return () => {
      cancelled = true;
    };
  }, [hasPasskey, whatsNewShowing]);

  async function turnOn() {
    setPending(true);
    setError(null);
    try {
      const { data, error } = await authClient.passkey.addPasskey({
        name: method.deviceName,
        authenticatorAttachment: "platform",
      });
      if (error || !data) {
        setPending(false);
        if (passkeyErrorKind(error) === "cancelled") setOpen(false);
        else setError(copy.turnOnFailed);
        return;
      }
      await rememberPasskeyAction(data.id);
      setOpen(false);
      router.refresh();
    } catch {
      setPending(false);
      setError(UNREACHABLE_MESSAGE);
    }
  }

  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <DialogContent className="fixed top-auto right-0 bottom-0 left-0 w-full max-w-full translate-x-0 translate-y-0 rounded-t-sheet rounded-b-none bg-surface-subtle pb-[max(2.5rem,env(safe-area-inset-bottom))] duration-150 data-closed:slide-out-to-bottom data-open:slide-in-from-bottom sm:max-w-full">
        <div className="flex flex-col items-center gap-4 text-center">
          <div className="bg-surface-tint text-accent-strong mt-2 flex size-16 items-center justify-center rounded-full">
            <PasskeyIcon kind={method.kind} className="size-8" strokeWidth={1.75} />
          </div>
          <div className="flex flex-col gap-2">
            <DialogTitle className="font-serif text-xl font-semibold">{copy.offerTitle}</DialogTitle>
            <DialogDescription className="text-muted-foreground text-base">{copy.offerBody}</DialogDescription>
          </div>
          <div className="mt-2 flex w-full flex-col gap-2">
            <Button size="block" onClick={turnOn} disabled={pending}>
              {copy.turnOn}
            </Button>
            <Button variant="outline" size="block" onClick={() => setOpen(false)} disabled={pending}>
              Not now
            </Button>
          </div>
          {error && <p className="text-destructive text-sm">{error}</p>}
          <p className="text-tertiary text-xs">You can change this any time in Settings.</p>
        </div>
      </DialogContent>
    </Dialog>
  );
}
```

```ts
import { expect, test, type BrowserContext, type Page } from "@playwright/test";
import { config } from "dotenv";
import { Pool } from "pg";
import { expectApp, memberContext, signIn } from "./helpers";

// A platform authenticator that always verifies the user, like Face ID that
// recognizes you. Chromium only.
async function addVirtualAuthenticator(context: BrowserContext, page: Page) {
  const cdp = await context.newCDPSession(page);
  await cdp.send("WebAuthn.enable");
  await cdp.send("WebAuthn.addVirtualAuthenticator", {
    options: {
      protocol: "ctap2",
      transport: "internal",
      hasResidentKey: true,
      hasUserVerification: true,
      isUserVerified: true,
      automaticPresenceSimulation: true,
    },
  });
}

// Removing the passkey from another device: the server forgets it while this
// device still holds the credential and the cookie.
async function deletePasskeysFor(email: string) {
  config({ quiet: true });
  const pool = new Pool({ connectionString: process.env.DATABASE_URL });
  try {
    await pool.query(`delete from passkey where user_id = (select id from "user" where email = $1)`, [email]);
  } finally {
    await pool.end();
  }
}

async function signOut(page: Page) {
  await page.getByRole("link", { name: "Settings", exact: true }).click();
  await page.getByRole("button", { name: "Sign out" }).click();
  await page.waitForURL(/\/sign-in/);
}

test("turn on passkey sign-in after a code sign-in, use it, and hear when it was removed", async ({ browser }) => {
  const email = `passkey-${Date.now()}@example.com`;
  const context = await memberContext(browser);
  const page = await context.newPage();
  await addVirtualAuthenticator(context, page);

  // A device without a passkey sees today's screen: no passkey button.
  await page.goto("/sign-in");
  await expect(page.getByLabel("Email address")).toBeVisible();
  await expect(page.getByRole("button", { name: /passkey/i })).toHaveCount(0);

  await signIn(page, email, "Pat");
  const offer = page.getByRole("dialog", { name: "Sign in with a passkey next time?" });
  await expectApp(offer).toBeVisible();
  await offer.getByRole("button", { name: "Turn on passkey sign-in" }).click();
  await expectApp(offer).toBeHidden();

  await page.getByRole("link", { name: "Settings", exact: true }).click();
  await expectApp(page.getByText("This computer")).toBeVisible();
  await expect(page.getByText("On", { exact: true })).toBeVisible();

  // Signed out, this device opens to Welcome back, and the button signs in.
  await page.getByRole("button", { name: "Sign out" }).click();
  await page.waitForURL(/\/sign-in/);
  await expectApp(page.getByText("Welcome back.")).toBeVisible();
  await page.getByRole("button", { name: "Sign in with a passkey" }).click();
  await page.waitForURL((url) => url.pathname !== "/sign-in");

  // Removed elsewhere: the server refuses it, and the form comes back with a notice.
  await deletePasskeysFor(email);
  await signOut(page);
  await page.getByRole("button", { name: "Sign in with a passkey" }).click();
  await expectApp(page.getByText("Passkey sign-in was turned off for this device.", { exact: false })).toBeVisible();
  await expect(page.getByLabel("Email address")).toBeVisible();
  await page.reload();
  await expect(page.getByText("Welcome back.")).toHaveCount(0);
});
```
